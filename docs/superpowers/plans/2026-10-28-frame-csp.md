# Frame CSP Implementation Plan

**Goal:** Enforce TASK-27's instance-only resource policy in opaque-origin editor frames and passive HTML previews.

**Architecture:** Prefix srcDoc documents with a CSP before any supplied markup. Reuse one browser helper in the bootstrap and all passive previews. Keep `sandbox="allow-scripts"` for the runtime and `sandbox=""` for passive previews; never grant same-origin access.

**Spec:** `docs/prowin/doop-fork-umsetzung.md` § 7.6, Q7; TASK-27 acceptance criteria.

## Constraints and decisions

- Preserve the existing uncommitted TASK-25/26 work, including fonts and tests.
- Work on branch `task-27-frame-csp` in the current checkout because the prerequisite font changes are uncommitted here. Do not stash, copy, or commit user changes.
- Allow the exact browser instance origin, not `'self'`, wildcard hosts, or arbitrary protocols.
- Keep inline styles/scripts needed by existing designs. Allow `data:`/`blob:` for images, fonts and media, not executable documents or workers.
- CSP is a resource policy, not an HTML sanitizer or navigation/network firewall. Server screenshot rendering retains its existing request guard.
- Track verification in Backlog; leave status In Progress until explicit user acceptance. No push/merge/commit requested.

## Review focus

- Policy must be parsed before resource-bearing markup, even with a supplied doctype/head or fragment.
- Removing the meta during a DOM morph must not remove enforcement.
- Same-instance assets must work from an opaque frame without weakening the sandbox.
- Executable blob/data documents must not bypass the resource allowlist.
- Parent-sourced messages and edited HTML must retain their existing behavior; runtime CSP metadata must not leak into persisted designs.
