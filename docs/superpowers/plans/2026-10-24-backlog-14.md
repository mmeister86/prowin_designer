# TASK-14 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Separate self-service Creator registration from owner-controlled workspace permissions, protect privileged operations, and document Q4.

**Architecture:** A proWIN account capability record is independent of Better Auth's instance admin role. Workspace roles govern shared Creator rights. Common server helpers enforce current capabilities across REST, MCP and agent entry points; the UI consumes server-provided capabilities.

**Tech Stack:** TypeScript, React, Express, Drizzle/Postgres/PGlite, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-24-creator-permissions-design.md` (approved in conversation).

## Review Focus

- Link-edit and direct canvas invites must not yield Creator rights.
- Removed workspace members who still own a canvas must lose workspace Creator rights.
- Local run tokens and queued tool calls must lose authority after role changes.
- Legacy workspace admins and pending invitations must migrate without becoming instance admins.
- Creator registration must persist and ignore supplied target-user/admin fields.
