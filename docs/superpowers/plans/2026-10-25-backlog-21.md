# TASK-21 Q10 Platzhalter-Schutz für Agent-Eingaben — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Echte Kontaktdaten (E-Mail, Telefon, IBAN) erreichen Requesty weder in Frame-HTML noch in Vision-Screenshots noch in Freitext-Eingaben; der Agent arbeitet mit reversiblen Platzhaltern, gespeicherte Frames behalten die Originale.

**Architecture:** Ein Redaktionsmodul `server/prowin/redact.ts` mit zustandslosem `redactPii()` (Einweg-Texte: Prompts, Kommentare, Distiller) und `createRedactionSession()` (reversible `[[PII-n]]`-Tokens pro Agent-Lauf für Frame-HTML-Roundtrip). Verdrahtung ausschließlich an den Server-Requesty-Pfaden in `resident.ts` (Tool-Ergebnisse + Kickoff + Frame-Writes-Restore, Screenshot/Inspect aus redigierter HTML-Kopie) und `distill.ts`. UI-Hinweis einmalig über das bestehende Onboarding.

**Tech Stack:** TypeScript, Vitest (`bun run test` / `npx vitest run`), React (Onboarding), puppeteer-Screenshot in `server/screenshot.ts`.

**Spec:** Backlog TASK-21; `docs/prowin/doop-fork-umsetzung.md` §§7.6, 17 (Q10); `docs/prowin/bezugsdokumente-referenz.md` R4.5–R4.6. Nutzerentscheidungen vom 25.10.2026: Option A (Platzhalter), Verantwortlicher: Matthias, Geltungsbereich nur Server-Requesty-Pfade (MCP/Local-Agent ausgenommen, Begründung in Task 3).

## Global Constraints

- Keine neuen Dependencies. Keine Änderungen an MCP (`server/mcp.ts`) und Local-Agent (`server/localAgent*.ts`) — deren HTML/Screenshot-Ausgaben bleiben unverändert.
- Gespeicherte Frame-HTML (`store`) wird niemals redigiert gespeichert; Redaktion nur in Kopien Richtung Modell, Restore bei jedem Frame-Schreib-Tool.
- Platzhalter-Tokens: `[[PII-1]]`, `[[PII-2]]`, … pro Session aufsteigend; Restore ersetzt exakt diese Tokens.
- Regex-Abdeckung: E-Mail, IBAN (DE + international, mit/ohne Leerzeichen), Telefon (deutsche/internationale Formate mit `+49`/`0`, Trennzeichen Leerzeichen/`/`/`-`, mind. 6 Ziffern). Namen und freie Adressen sind per Regex nicht zuverlässig erkennbar — `shortcut:`-Kommentar im Modul, Upgrade-Pfad `data-od-role="contact"` (TASK-29).
- Fehlertexte/Logs dürfen keine Original-PII enthalten.
- Backlog nur per CLI pflegen; TASK-21 nicht ohne ausdrückliche Nutzerabnahme auf Done setzen.

## Review Focus

- Agent umgeht Redaktion über einen nicht verdrahteten Pfad (get_reference-HTML, inspect_frame-Text, angehängte Referenz-Frames im Kickoff) → Task 2 testet jeden Ausgang.
- `edit_frame_html`: Agent kopiert `find` aus redigierter Sicht — Restore muss auf `find` und `replace` laufen, sonst „find not found" oder Token landet im Store → Task-2-Test.
- Screenshot zeigt Original, weil `renderFrame` das unredigierte Frame bekommt → Task-2-Vision-Test über Fake-Router-Payload.
- Regex-False-Positives zerstören normale Design-Texte (Datumsangaben, Preise, Maßangaben wie `120 x 80`) → Task-1-Tests mit Nicht-Treffern.
- Token-Kollision: Nutzer-HTML enthält bereits `[[PII-1]]` → Restore darf fremde Tokens nicht ersetzen; Task-1-Test.
